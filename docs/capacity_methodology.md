# 过去成交量约束下的执行可行性 · v0.16

本轮回答：原1000万元规模的三个固定组合，在只依据过去成交量限制每次下单手数、允许延迟执行后，持仓、费用、资金和业绩会怎样变化？这是已看过历史上的新增执行敏感性实验，不是独立样本验证或因子发现。

原审查已发现模拟单笔交易最大约占全天报告量60.5%。这不是按未来数据调整订单的依据，而是本轮事先明确执行规则的动机。既有负结果和原账保留。

## 固定范围

- 沿用v0.14主情景三个组合、十品种、2023—2025、每5交易日生成信号、初始1000万元、固定初始名义预算。使用原保存目标，全部目标与修复失格退出后的生成器逐项核对；不根据新结果改合约、因子、权重或资金规模。
- 固定单边总摩擦5bp、保证金20%、权益保证金预算50%、原记录开盘价和结算价。保留原时钟占位与历史修订假设，资金闲置不计息。
- 三种执行情景全部报告：原无容量限制的完整成交基线；前20交易日同合约平均成交量的1%；相同平均量的5%。后两者均向下取整到整数手。1%/5%是固定的研究压力参数，不是交易所标准，也未经证明适合开盘竞价。
- 按原完整交易日历逐合约重排后，使用严格早于执行交易日的20个交易日成交量。零成交计入均值，缺失不填零、不跳过；任何缺失或上市历史不足20日，容量为0手。容量可用时钟沿用前一日20:30回溯假设。

## 未完成订单和换月

- 有容量的情景按整数手分日执行，某合约当天全部实际调整量绝对值不超过该日过去量预算。多空反转的平仓和新开仓都消耗容量，并只对实际成交收费。
- 每次新信号是该品种的完整新目标，取消未完成旧目标。没有新信号时，前一目标继续在后续开盘尝试；不因缺少新信号丢弃未完成目标。每日重试使用当日之前的量重新计算预算。
- 换约先减少旧合约，只有旧合约全平，才允许建立新合约；同日旧约全平后可用新约自身预算建立部分新仓。方向受阻时保留旧仓并延迟新仓，不制造意外跨月双持。
- 有容量的新策略是分阶段换月，区别于原无容量账的同品种原子换月。容量对开、平、反转、强制处置和终端清仓均适用，不为保证净值好看而豁免退出。
- 有效分阶段订单仍按原品种顺序检查保证金。若拟执行整组造成预算拒绝，整组实际成交为0；下一日重试。超预算触发下一开盘清仓，处置目标持续直到完成或被后续新信号替代。终端仅尝试当日预算内清仓，未清部分保留估值和显式标志，不伪造清仓。
- 必要价格缺失、持仓越过到期等使该本账失败并保留原因；不填价，不事后删品种。其他固定情景仍继续，失败不能消失于汇总。

## 输出、验证和结论

保存过去量表、三个原订单表、每本资金/成交/持仓/拒绝/容量事件，以及每日期望和实际偏离、未完成量、旧约延迟和终端残留。原无容量三个账必须复现原资金、成交和持仓的数值，才能解释新结果。每日权益可以含未清头寸，因此终端未清的累计回报必须标为盯市权益回报，不能当作全部已实现现金收益。

新增研究问题记为第17项探索；不计算p值、置信区间或最优参与率，完整报告1%和5%。旧16项原字段保留，新的保守BY列不能恢复真正事前样本资格。

每日成交量预算只能揭示规模与延迟敏感性，不能证明开盘存在相应数量的对手盘。实际市场冲击、盘口、竞价量、涨跌停、部分成交概率、平今费用和历史规格仍未认证；本轮不模拟任意一个价格冲击公式来填补这些缺口。

方法背景：[Interactive Brokers官方成交量参与算法说明](https://www.interactivebrokers.com/docs/general/order-types/algorithmic-orders/ib-algorithms/percentage-of-volume)说明了用成交量约束订单参与程度的思想。其产品设置不构成本研究参数的中国期货适用性证据，本文的过去量硬预算也不等于该实时算法的复现。
